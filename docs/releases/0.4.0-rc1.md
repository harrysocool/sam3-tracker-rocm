# SAM3 ROCm 0.4.0-rc1

This release candidate moves the supported GPU runtime from the ROCm 7.14 /
MIGraphX 2.17 / ONNX Runtime 1.24.2 bundle to the official AMD ROCm 10.1
packages. The 7.14 runtime is no longer supported; `v0.3.0-rc1` remains the
last release for it.

## Runtime

- ROCm 10.1, Torch 2.14.0+rocm10.1.0, MIGraphX 2.18.0+rocm10.1.0, ONNX Runtime
  1.29 with the `onnxruntime-ep-migraphx` 1.0.0+rocm10.1.0 plugin execution
  provider. All wheels come from AMD's official indexes (and PyPI for ONNX
  Runtime) and are SHA256-pinned in `docker/rocm101/build.sh`.
- The custom MIGraphX build with the FC1-sink rocMLIR patch and the
  self-built ONNX Runtime wheel are removed.
- The container is `docker/rocm101/run.sh`; `docker/rocm714/` is removed.

## Code changes

- `tracker/ort_plugin_ep.py` creates every ONNX Runtime MIGraphX session. It
  registers the plugin EP, uses the plugin's option keys, and raises if any graph
  node is not assigned to MIGraphX. The plugin EP otherwise falls back to CPU
  silently when it rejects an option.
- GPU I/O binding uses DLPack `OrtValue`s; `bind_input("cuda", ...)` is not
  supported by the plugin EP.
- Hybrid-mode memory attention (`sam3_onnx_tracker.py`), the fixed decoder
  compiler, the memory-attention compiler and the ORT prewarm script use the same
  factory.
- Importing `tracker` no longer sets `MIGRAPHX_SKIP_BENCHMARKING`, so build
  scripts that clear it before importing `tracker` keep full autotuning.
- The release gate, container test runner, live smoke, canonical benchmark and
  artifact manifest validate the exact supported stack
  (`tracker.ort_plugin_ep.SUPPORTED_STACK`) instead of provider names.

## Artifacts

MXR and ORT cache files built with MIGraphX 2.17 cannot be loaded by 2.18 and
must be rebuilt with `./setup.sh --models`. Artifacts are selected with
`SAM3_ONNX_DIR`; the wrapper default directory changes from
`inference/production/rocm714-mgx217-504` to
`inference/production/rocm101-mgx218-504`.
